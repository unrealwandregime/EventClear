# Zero-cost prototype deployment

Cost ceiling: **PROTOTYPE_MAX_MONTHLY_COST_USD=0**. No payment, trial that can
charge, paid plan, custom domain purchase or gas purchase is authorized.

## Provider selection and verification boundary

Candidate topology: one Render **free** Docker web service with its generated
HTTPS hostname, Neon **free** PostgreSQL, Upstash **free** TLS Redis, and Polygon
Amoy with faucet gas and free HTTPS RPC endpoints. These are replaceable
providers; the core application uses standard PostgreSQL, Redis, HTTP and EVM
interfaces. The checked-in `render.yaml` explicitly selects `plan: free` and
turns automatic deploys off. It creates no paid database, Redis or AWS resource.

The current execution environment returns HTTP 403 for the official Render,
Neon and Upstash pricing pages. Current free-plan availability, card policy,
quotas and account eligibility are therefore **NOT VERIFIED**. Before connecting
an account, verify official terms at https://render.com/docs/free,
https://neon.com/pricing and https://upstash.com/pricing/redis. Select only an
explicit $0 plan with no automatic paid upgrade. If any candidate fails these
conditions, use an equivalent free provider or remain local; do not pay.
Render's free service may sleep or exhaust its monthly free usage. Measure the
combined container against the provider's current RAM/build limits; an untested
free-tier fit is not a deployment success. Never manufacture uptime with
keepalive requests. PostgreSQL and Redis must be separate persistent free
services, never an ephemeral container filesystem.

## One owner setup checklist

1. Connect genuinely free hosting, PostgreSQL and Redis accounts; no card/paid
   trial is required by this implementation. Verify free limits and disable paid
   upgrades. Use the generated HTTPS hostname, not a purchased domain.
2. Create five dedicated testnet identities. Keep transaction keys in a protected
   GitHub `prototype` environment and the risk key in host secret storage. Do not
   enter private values into chat or commit them. Fund deployer, LP and tester
   using faucet test gas only. If unavailable, status is `TESTNET_GAS_REQUIRED`.
   `node scripts/prototype/actor-addresses.mjs` prints only derived public
   addresses and identifies the three actors requiring faucet gas.
3. Set protected runner secrets `PROTOTYPE_DEPLOYER_PRIVATE_KEY`,
   `PROTOTYPE_LP_PRIVATE_KEY`, `PROTOTYPE_TESTER_PRIVATE_KEY`,
   `RISK_SIGNER_PRIVATE_KEY`, `RPC_PRIMARY`, and preferably `RPC_FALLBACK`.
   Set nonsecret `PROTOTYPE_ADMIN_ADDRESS`, `PROTOTYPE_CHAIN_ID=80002` (workflow variable;
   CLI uses `CHAIN_ID=80002`),
   `PROTOTYPE_MAX_MONTHLY_COST_USD=0`, `EVENTCLEAR_MODE=testnet-prototype`,
   `TESTNET_ASSETS_ONLY=true`, `ENABLE_MAINNET_EXECUTION=false`,
   `PUBLIC_CAPITAL_ACTIVATED=false`. The CLI derives other actor addresses and
   rejects a mismatching supplied address pin. The risk key is needed during
   isolated deployment/lifecycle preflight, never written to disk.
4. Deploy the reviewed mock suite using `node scripts/prototype/deploy-contracts.mjs`.
   It verifies current official network metadata, both RPCs (or explicit degraded
   mode), roles, caps, signer, bytecode and solver fixture. Run `node scripts/prototype/host-config.mjs` to derive the public host
   settings automatically (also generated by the deployment workflow). Preserve the generated
   public manifest `config/contracts/testnet-prototype.json`, canonical
   `config/staging/deployed.json` and sanitized deployment evidence. Do not upload
   raw Foundry broadcast/cache or any key. A rerun after resolution needs a fresh
   fixture/contracts and separate database, never a reset of public chain state.
5. Create the free web service from `render.yaml` at the reviewed immutable SHA.
   Enter `DATABASE_URL` (provider TLS/verify-full), `REDIS_URL` (`rediss://`),
   risk key/address and random access/admin/session secrets directly in host
   secret storage. Do **not** put deployer/LP/tester keys on the host. Bind public
   metadata `PROTOTYPE_MANIFEST_JSON`, `PROTOTYPE_FIXTURE_JSON`, the four
   `PROTOTYPE_{DEPLOYER,LP,TESTER,ADMIN}_ADDRESS` pins, `POLYGON_RPC_URLS`,
   `SIWE_DOMAIN`, `SIWE_URI` and `INDEXER_START_BLOCK` from deployment receipts.
   The supervisor derives contract addresses and allowlists. Never start index
   scans at testnet genesis. Use a fresh database for each new manifest.
6. Wait for `/api/v1/readiness`. Obtain the generated server-side access token
   through the owner's host secret UI and enter it at `/staging/access` over
   HTTPS. No credential is embedded in frontend assets.
7. Set runner `PROTOTYPE_URL`, access token and `PROTOTYPE_PREVIOUS_SHA` to a
   compatible reviewed immutable revision. For automated Render restart/rollback,
   bind `RENDER_API_KEY` and `RENDER_SERVICE_ID` in protected runner secrets.
   The adapter checks the existing service is `free` before any redeploy and
   never changes billing or plans. A previous revision must support this mode and
   migration schema; the old AWS-only baseline is not a valid rollback target.

## Protected workflow commands

Create a reviewed `prototype` GitHub environment with a required reviewer and a
custom `master` deployment-branch rule. The workflow checks protection before
binding secrets; it never creates an unprotected environment implicitly. After
review/merge and secret setup:

```bash
gh workflow run testnet-prototype.yml -R unrealwandregime/EventClear \
  -f action=deploy-contracts -f release_ref="$REVIEWED_RELEASE_SHA"
gh workflow run testnet-prototype.yml -R unrealwandregime/EventClear \
  -f action=remote-lifecycle -f release_ref="$REVIEWED_RELEASE_SHA" \
  -f evidence_run_id="$CONTRACT_DEPLOYMENT_RUN_ID"
```

The workflow verifies default-branch ancestry and successful CI, restores only
hash-verified deployment evidence from the trusted workflow and uploads sanitized
results. It never pushes generated evidence to master. Review/promote public
metadata on a dedicated PR with `EVIDENCE_RUN_ID` bound, using
`node scripts/prototype/promote-evidence.mjs` from a clean reviewed checkout. Keep GitHub spending limits at $0; public-repository
hosted CI is the intended free execution path, not purchased Actions capacity.

## Reproducible commands

```bash
source .tools/activate
make install
node scripts/prototype/deploy-contracts.mjs
docker build -f infrastructure/docker/prototype.Dockerfile -t eventclear-prototype:"$(git rev-parse HEAD)" .
node scripts/run-testnet-prototype-lifecycle.mjs
node scripts/prototype/health.mjs
```

Supply secrets through protected environment bindings, not command arguments or
shell history. All runtime metadata is public; no generated address is checked
in until actual deployment evidence exists. The image needs no AWS download.
On enterprise networks an optional BuildKit `build_ca` secret supports a trusted
proxy CA; TLS and package integrity validation remain enabled.

The full lifecycle includes remote UI analysis/quote, LP deposit, SIWE, proof
reproduction and content hash, signature recovery, exact approval, financing,
indexer comparison, combined-host restart, durable records/Redis probe,
resolution, settlement, principal/residual redemption and pool/treasury/claim
reconciliation. Remote restart/rollback require host redeploy authorization;
missing credentials fail acceptance rather than silently skipping it.

Rollback redeploys `PROTOTYPE_PREVIOUS_SHA` without schema downgrade. Preserve
previous/current SHAs, host deployment IDs, manifest hash and migration ledger
in evidence. Do not destroy databases or contract state. Free-provider controls
may not permit a remote Redis outage drill: record `REMOTE REDIS FAILURE DRILL
NOT AVAILABLE` separately from isolated software fail-closed verification.

## Monitoring and future paths

`prototype-health.yml` is manual or opt-in weekly (`PROTOTYPE_MONITORING_ENABLED=true`).
It intentionally wakes the service only for a bounded health check, verifies
readiness dependencies and access barrier, and stores a sanitized report.
GitHub workflow failures are the free notification mechanism; the owner must
configure their GitHub notification preferences. No paid monitoring is required.
Do not claim a delivered alert until an actual failed check notification is seen.

AWS infrastructure remains under `infrastructure/aws/` as **OPTIONAL FUTURE
FUNDED STAGING / PRODUCTION-LIKE INFRASTRUCTURE**. It is not a prerequisite for
this prototype. Its provisioning still requires an explicit funded budget and
`ALLOW_AWS_PROVISION=true`; this sprint authorizes neither AWS provisioning nor
any expense.
